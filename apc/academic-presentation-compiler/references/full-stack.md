# 从任务书走到可打开的成品

本文件用于实际做成品或跨工具交接，不改变 Prompt 0 的任务书边界。先定位用户要求停在哪一步。以下角色可以由同一代理完成；能力未验证前，不把某个连接器、子代理、数据库或渲染器写成已完成。

## 1. 编译、检索与视觉输入

1. **编译**：盘点用户材料，运行 Prompt 0，发布 v001。先由学术任务推导证据和版式需求；用户指定的机构模板先作为硬约束登记，不替代科学判断。
2. **分流**：按 R 派发科研检索，按 V 发送 Style Search Brief、Layout Needs 与限制给视觉检索。若已安装 `scientific-evidence-asset-acquisition`，读取其入口，把科研证据与素材获取交给这个 Prompt 2 主路线：传任务书、当前索引、Given 和负责的 C/R/S/V；根据需要选择全量、Given 审计、定向或更新，返回 `EVIDENCE_PACKAGE/`。新证据/冲突由 Prompt 0 审定，包内 READY 不直接覆盖任务书；科学/素材就绪与 Prompt 1 的版式覆盖分别检查，再以同步的基线交给下游。未安装时沿本段原有科研检索路径执行。并行只在任务边界可分离时使用。科研返回来源定位、图号、图注、条件、单位、控制组、适用范围和相反证据。已读范围分为全文、摘要、用户原始数据；未获取用户实验不能由外部文献补填。用户要求查文献、前沿或引用时，使用可用检索工具打开原始来源核验，并保存直接来源。
3. **参考版式**：先检查用户参考件或模板。若已安装 `academic-presentation-reference-design`，把它作为 Prompt 1 主路线：传当前 `PPT_REQUIREMENTS.md`、已有 `PPT_HANDOFF.json`、Given、需要解决的 S/V 及其 04/07 定向路线；读取其 SKILL.md，按发现 / 给定 / 修订模式产出并校验 `PPT_REFERENCE_PACKAGE/`。将覆盖报告和设计回执交给 EVIDENCE UPDATE 复核；下游拿当前任务书与已同步版本的设计包。只在未使用 Prompt 1 主路线时走本段后续工具路径。如果任务需要定向学术样张且可用本机 `sci-deck-master`，加载它的入口与相关流程，仅在本阶段使用其样张探测和风格逆向路径。检查工具的真实位置、依赖和 `--help` 后再使用；其常见入口是 `scripts/probe_academic_deck.py` 与 `scripts/reverse_deck_style.py`。样张必须实际打开；分别记获取、可读、相关、可复用。将版式母版/画布、字号层级、边距、颜色、图占比和容纳的谱图/反应式/多面板原型写为已观察事实，提取结果标明页码与限制。没有可复用样张时，按硬约束制作本地版式样张，不声称逆向过参考件。
4. **回填**：Prompt 0 EVIDENCE UPDATE 合并科研和参考反馈，完成 WHAT↔HOW 复核；原始要求和科学边界优先。证据不能公平比较时，不做统一排行；可以并列展示原条件或改成待验证问题。记录版本和受影响页，冻结当前制作基线；冻结不代表拒绝后续证据。

## 2. 选择并验证一条制作路线

- **用户指定引擎、已有工程或需保留母版**：先读取指定技能或工程说明，沿用已验证的工作流。现有 PPTX 修改时保留副本；检查模板、布局、主题、占位符、原生元素和成品。只要对科学内容、页序、声明或约束有影响，回写任务书。
- **复杂原生制作或模板还原**：可选 `ppt-master` 的对应路线。先读其实际入口，执行其规定的准备/完整性检查，再读对应 route；不要拼接两个生成流程或跳过该工具自己的门槛。将 S/V 导出为其规格，并保持页序到 Slide ID 的映射。已有有效品牌配置及 `.deck.md` 时，也可选 `build-deck`；将结构化内容转成其规范，按它的品牌/模板流程执行。
- **常规本地 PowerPoint**：读取可用的 `presentations` 技能以及适用的设计、模板和运行时说明；在 Codex 中先用 `load_workspace_dependencies` 获取真实依赖。如果选用已安装的 `presentations` 路线，按其 implementation/finalization 说明走捆绑的 `@oai/artifact-tool`：按其说明设置运行时变量（包括校验子进程读取的 RUNTIME_NODE_MODULES）、在私有构建目录链接依赖，实际运行 JS 生成草稿、校验/写入最终 PPTX，再渲染全稿。其他引擎只在独立选用且相应工作流允许时使用，不替换已选路线的运行时。依赖检查成功不等于已经构建。不要从零实现文件格式，也不要把截图作为整页冒充可编辑交付。编写并实际运行项目生成脚本，生成源和素材交接给下轮。图表选择原生数据图、可编辑矢量或按要求保真引用原图；说明例外，保留轴、图例、单位、条件与出处。Google Slides 等目标走其实际连接能力，不能用本地 PPTX 冒充已写入目标平台。
- **验收能力**：按现有工具选择与目标相匹配的渲染器。确认工具文件、用法及依赖实际可用；例如随 `presentations` 提供的 `container_tools/render_slides.py`、`slides_test.py`，运行前先检查 `--help` 和所需后端；Windows 有可用 PowerPoint 时可通过 `PowerPoint.Application` 以只读方式打开工作副本并导出 PNG；不要终止用户正在使用的 PowerPoint。无法在目标软件实测时，报告已用的实际渲染器与未测试的目标，不声称兼容。

传给制作端：当前版本任务书与索引、生成规格、版式/参考约束、素材路径和出处、审校要求。制作端回填：实际生成命令、输入/输出、渲染器、S→实际页号映射、失败项和不可编辑元素（含原因）。拿不到数据的关键页只可进标注草稿；不能用猜测补绘结果。硬约束冲突不能由下游静默决定，返回可选修复并合并后再发布。

## 3. 构建、双检与返修

- **构建前**：人工检查任务书与索引一致；新交接用 `--strict-assets` 校验。另查 APRD 对硬依赖的实际核验与上页用途，不以版式 COVERED 代替。若仍有阻塞，发布区分清楚的草稿或任务书，除非有可靠的替代方案通过复核；不要将未过门的页称为最终版。
- **学术验收**：按 S→C/E 检查每页标题、结论限定、原图出处、原始单位、误差、对照、数据同条件可比性、结构式/符号和用户/文献结果分账。按任务检查叙事、章节时长、必讲内容、补充页及演讲者备注。
- **文件和视觉验收**：重新打开 PPTX，核对页数、对象、母版、编辑性、媒体和字体；实际渲染全稿并检查页面图像，重点查越界、意外遮挡、标题溢出、轴标、脚注、公式及投影阅读。包结构通过不代表无视觉问题。动效、音视频、讲者视图及 WPS/PowerPoint 兼容性仅记录实际验证到的项。
- **返修与交付**：排版小修改生成源或模板实例并复验；若需换结论、拆页或修改硬约束，提交回执、更新上游、重建受影响页并检查全稿回归。交付前用 `validate --final`，如有旧版加 `--previous`。给出最终文件、必要生成源和证据清单/验收记录；注明仍待确认的项目，保留用于后续修改的版本和映射。
