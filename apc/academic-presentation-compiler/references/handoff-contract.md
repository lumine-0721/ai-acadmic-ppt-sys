# PPT 全栈交接协议

## 文件与权威

- `PPT_REQUIREMENTS.md`：Prompt 0 的 00–09 章节原样保留，包含项目号、版本号、原始任务、硬约束、状态、变更记录；是唯一需求依据。首行标题下放 `Project-ID: ...` 与 `Revision: 1`，后续递增。按章节编号写 Markdown 二级标题，例如 `## 00. Mission Contract — 任务定义`。
- `PPT_HANDOFF.json`：给工具消费的最小派生索引。用于跨工具交接、自动验证和影响分析。不把全部任务书复制进 JSON。不向检索代理发送与其任务无关的实验原始数据。
- `revisions/v001/` 等：在更新前保留上个已发布版本的需求文件和索引；新版本在草稿区验证通过后发布。不要让多个代理同时写活跃版本。按所用工作区工具记录版本；同名文件不代表同版本。
- `feedback/`：检索、风格、制作和 QA 都以回执提出建议，不直接改需求文件。任何失败都返回实测结果、失败层、涉及 ID、约束、修复建议。并行代理各写独立回执；过期结果按最新版本重审，冲突不按最后写入者覆盖。
- `build/`：保留生成源、素材路径、成品、渲染预览、可编辑对象说明、页序→Slide ID 映射、验收记录。目录名可随项目改，稳定的是接口和关联。

## ID、状态和引用

按 Prompt 0 使用 M001 材料、C001 主张/问题、E001 证据、R001 检索/获取任务、V001 视觉需求、S001 页面。ID 不随排序变化，不回收。实质不同的研究问题、证据或页面获新 ID；修正同一个问题的措辞或支持程度可沿用。删除时置 `retired: true`，记录替代项；活跃记录不引用退役记录。

每条记录都有 `summary` 和 `depends_on`（可以为空），表示本记录读取或受哪些上游记录制约；新交接中 S/V 直接引用的 R 一律是当前画法的硬依赖，未采纳的升级候选仅在任务书中引用：

| ID | 可依赖的 ID | 其他字段（按需继续丰富任务书） |
| --- | --- | --- |
| M | 无 | `source`：可解析的文件路径、URL 或口头材料出处；附日期/范围时写入任务书。 |
| E | M | `status`、`origin`：`user`/`literature`/`other`；`source`、`locator` 精确到页码/图/数据行；可加条件、单位、对照和限制；`supports`、`opposes` 为非依赖关系，指向 C。 |
| R | M、E | `status`：`OPEN`/`IN_PROGRESS`/`DONE`/`BLOCKED`；`target_claims` 指向 C，不作依赖；`result_ids`（非依赖）指向 E。任务书写检索式、结果、纳排条件与验收标准；DONE 至少有证据或记录无结果/冲突且搜索到停止条件。 |
| C | M、E、R | `status` 同 Prompt 0；`kind`：`finding`/`inference`/`hypothesis`/`question`/`context`；`origin`：`user`/`literature`/`mixed`/`other`/`not_applicable`；`disclosure`：需让观众看见的限定语。无证据的新事实不归入 context。 |
| V | M、C、E、R | `status`：`READY`/`PROVISIONAL`/`BLOCKED`；`kind`：`empirical`/`schematic`/`layout`；实证图依赖对应 E；机理示意保留假说标记。 |
| S | M、C、E、R、V | `status`：`READY`/`PROVISIONAL`/`BLOCKED`；`reviewed_in`：本页最后实际复审的版本号。READY 表示内容和约束足以进入制作，不是已通过渲染。 |

E/C 的证据状态使用 `VERIFIED`、`USER_PROVIDED`、`INFERRED`、`HYPOTHESIS`、`TO_RETRIEVE`、`BLOCKED`。前两种 E 都应有确切来源与定位；状态提升基于核验，不基于发现了一个链接。结论型 C 若为 VERIFIED，需直接关联 VERIFIED 且支持它的 E；用户结果还需至少一条用户证据。用户已提供但未独立核验的结果可以按原始记录展示，前提是有相应的用户 E 且页面显式注明范围与状态。推论与假说在页内标注；反证存在时记下为何削弱或不改变结论。READY 的 S 不得引用未就绪的 V 或 BLOCKED 的 C。

顶层例子（不是数据模板，实际项目填满任务所需条目）：

```json
{
  "project_id": "group-meeting",
  "revision": 1,
  "records": {
    "C001": {"summary": "哪项条件仍需测量？", "kind": "question", "status": "TO_RETRIEVE", "origin": "not_applicable", "depends_on": []},
    "S001": {"summary": "提出需要讨论的问题", "status": "READY", "reviewed_in": 1, "depends_on": ["C001"]}
  },
  "slide_order": ["S001"]
}
```

`slide_order` 是全部活跃 S 的顺序（可以在早期为空）。临时样张/待证页面不进入最终版；移入附录也需先过相同证据门槛，纯占位页移出时退役并记录。

## 逐页素材定位

只为影响叙事、证据或版式的关键页提供定位条目；可按共用素材或页面功能合并，不逐页凑条数。写回现有任务书，不另起素材清单文件。06 节按 S/V 指到 04 节的 R 或 07 节的参考条目；上游有 JSON 时仍沿用已有 ID 和字段。发布前按以下区别检查：

| 要找什么 | 写到哪里 | 优先从哪里找 |
| --- | --- | --- |
| 科学素材：原始曲线、反应式、结构、谱图、数据 | 04 节现有 R；已核证据关联 E | 允许使用的用户原始数据或随附文件；否则从已知 DOI/原论文、补充材料或对应数据仓库入手。跟出版者入口时，以作者机构库、同一论文的开放版本或数据记录为备用；综述或讲义中的转引先追原出处，不自动当原图。 |
| 版式参考：图、表、条件、结论如何同页呈现 | 07 节按 S/V 或页面功能写 | 用户模板或历史稿优先；其次找实际使用该页面结构的院校组会、会议公开报告或课程讲义。优先同场景，缺口按信息结构跨题材补查；不要把题目直接当检索词。 |

**编译时先走一次入口。** 对已有 M/E、给定模板及关键优先入口，在权限和工具允许时实际打开并尽量跳到目标；先利用项目缓存，复用已核对的同版本来源，不要求 APC 把所有候选都查完。公开来源给可持久引用的页面（如 DOI 或机构库条目）及页内锚点；若提供媒体直链，同时保留上一级正文入口。PDF 写清是文件页还是印刷页；数据写文件名、表/列与筛选条件。传本地素材用工作区绝对路径或相对任务书的路径，并注明跨会话不可达时的备选。

每条路线单独写（同一个 V 可以有版式路线和科学素材路线，也可以有多项素材）：

> S/V（有则附 R/E）｜素材类型与预期对象｜本版用途与必需/可选｜优先入口 → 精确定位｜已核到哪层｜备用入口或可复制查询式｜命中/排除条件｜找不到时的当前画法、解除条件与责任方

精确定位能直接跳到目标时才写；只到题录、摘要或预览时标为「定向待找」，用可执行的查找路线代替猜页码。备用路线要改变失败路径：科学素材换同一来源的合法版本/入口；版式换机构语料或按页面结构跨题材。交接前从 APRD 的视角重放一条关键路线：不依赖前一轮聊天也能找到入口、认出目标、决定能否开始。

每个条目让接手者能回答四件事：

1. **要找哪一项，拿来干什么**：S/V（有证据时加 C/E/R）、版式参考或科学素材、预期拿回的具体对象。比如「同一体系的输入—产出曲线，要求两轴、基线和反应条件同在」，而非「找手性配图」。
2. **先点哪里、点开后找哪里**：能定位就给具体文件/入口、DOI 或可打开链接，再给 Figure/Scheme/Table、页码、章节或数据文件名；写清已核到哪一步。若只核到题录或尚无确切入口，标为候选，给优先站点/仓库、作者或题名、独特术语和一条可直接跑的查询式；给能解决当前缺口的备用路线。禁止猜链接、页码和图号。
3. **怎样算找对**：列能区分对错的少数条件。科学素材核对象、变量、单位、底物/条件、版本及引用或重绘要求；版式参考核页面角色、图文结构以及轴标、条件和来源位是否容得下。明确哪些细节仍需 APC 或研究者核验。
4. **缺它现在能否开做**：只有缺失会使当前方案失效的 R 才是该 S/V 的硬依赖；若当前可用合规重绘或定性示意，把未完成的原图检索写为可选升级，保留可追踪引用但不要写入该 S/V 的 `depends_on`。必须用原图却无合格替代时，将受影响 V/S 标为待定或阻塞，说明下一责任方及解除条件。

APRD 可以打开已给或定向查找指定素材，复核其位置、可读性、格式和使用方式；新科学结论、来源冲突或实证替换回给 APC 审定。禁止外查时只写允许使用的给定入口和现有缺口，不派外部检索。

## 回执、逆向反馈与验收

每次派发写清：`project_id`、`base_revision`、`stage`、`task_ids`、负责角色、输入（路径和条目 ID）、验收条件、产物目录。每份回执返回这些定位键，外加：
- `result`（`accepted` / `partial` / `blocked` / `conflict`）、`affected_ids`、`artifacts`（路径或 URL、具体定位）、`observations`、`proposed_changes` 和 `checks`（命令/输入、结果、版本）。找不到证据也回填尝试范围、限制与可选路线。
- 制作端遇到谱图轴标过密、画布装不下、图像许可或编辑性约束时，给出可重现的页号、画布/对象、实际表现和候选方案，按 V→C/E→S 回推；不能静默裁轴、删对照、删除不利数据或改结论。
- 负面或冲突证据由 E→C→V/S 回推；实测更新可让结论降级、改为假说或调整对比图。任务统筹先审科学意义和硬约束，再合并到新修订、保留旧版本，重跑受影响链条。合并记明采用/拒绝原因、影响 ID、复审对象。改变全局时长、模板、主题字体等不在 ID 图里的约束时，人工把受影响范围扩大到全稿。

## 确定性检查

用本技能实际目录替换 `SKILL_DIR`，用项目文件实际路径替换文件名：

```text
python SKILL_DIR/scripts/check_handoff.py validate PPT_REQUIREMENTS.md PPT_HANDOFF.json --strict-assets
python SKILL_DIR/scripts/check_handoff.py impact revisions/v001/PPT_HANDOFF.json PPT_HANDOFF.json
python SKILL_DIR/scripts/check_handoff.py validate PPT_REQUIREMENTS.md PPT_HANDOFF.json --previous revisions/v001/PPT_HANDOFF.json --final --strict-assets
```

`impact` 按旧/新记录、顺序和双向关联报告增删改与受影响页面；旧版存在时 `validate` 加 `--previous`，确保同一项目、版本递增、ID 不消失，影响到的 READY 页面须在当前版复审。初版最终检查省略 `--previous`。新交接使用 `--strict-assets`；它拒绝 READY 的 S/V 直接依赖未完成的 R，兼容读取旧索引时可省略。R 为 DONE 只表示任务已收尾；若收尾结论是无合格素材，仍须人工复核，不能把原图方案标 READY。脚本不判定论文质量、证据含义、MD 与 JSON 的语义一致性或 PPTX 是否合格；人工与实际工具承担这些验收。
