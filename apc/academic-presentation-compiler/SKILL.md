# 学术演示任务编译器

把用户的交流目标、科学证据和表达方案写成可追溯的制作任务；需要成稿时，按同一份任务书接到实际生成和验收，不把大纲冒充成品。

## 先判定这一轮要到哪里

| 用户要做什么 | 本轮交付 |
| --- | --- |
| 讨论思路、取舍或下一步 | 在对话中说明当前判断、依据和取舍；不擅自新建项目或启动制作。若已存在任务书，先读相关章节。 |
| 编译需求、列出检索和页面计划，或只给了模糊题目且未明确要成稿 | 落盘 `PPT_REQUIREMENTS.md`，执行 Prompt 0 的 INITIAL COMPILATION；不写整套页稿，不导出 PPTX。 |
| 回填文献、实验、参考样张、排版或审校反馈 | 执行 EVIDENCE UPDATE，保留有效要求和 ID；按用户要求停止在修订任务书或继续返修文件。 |
| 明确要交付或修改成品 | Prompt 0 仍只负责编译/修订；再进入制作阶段，实际生成或修改文件，打开和检查成品。不能用一份任务书代替成品。局部改动沿用原项目，不为小修重编整套；没有既有任务书时只做变更所需的最小审计。 |

同轮可以先讨论后执行。只有答案会实质改变目标、约束或可交付结果时才问；其他未知项写为可调整假设，解释其会影响什么。不要强迫用户逐项填表或等待无必要的确认。每次说明实际到了哪一阶段、哪些判断仍未落实、接下来的决策或动作是什么。先判定谁在被评、评什么：若原话可能指「演示作品被评」或「受众答题被评」，且答案会改变交付物或检索来源，只问一句区分两者；可先继续已明确的场景。

## 编译与证据更新

1. 进入任一编译/更新时，**从头到尾读取并执行** [Prompt 0 完整原文](references/prompt-0.md)，不是只读摘要或前几节。原文的七类场景、WHAT↔HOW 反馈、六种证据状态、材料审计、分层检索、叙事、风格、00–09、两种模式和 15 项自审全部生效。角色、先后和交付边界按原文执行；“只生成任务书”约束的是 Prompt 0 阶段，不禁止用户另外明确要求的后续制作。仅讨论时读取回答所需的部分。
2. 先读已提供材料和既有项目，记录已读范围及无法打开的附件。先判断任务、观众和要形成的判断，再拟定证据与页面；用户明确的范围优先：禁止外查时只用允许的材料，相应章节写明不适用或待验证；否则在有检索条件时做必要侦察。无论是否外查，搜索结果都不替代用户实验。先完成一轮内容→证据→表达→内容修正，再发布任务书。任务书保留 00–09 全部章节；空项写明不适用或缺口，不用虚构内容填表。默认用用户语言。
3. `PPT_REQUIREMENTS.md` 是唯一语义权威。全栈制作、跨会话/跨工具交接或需要自动化返修时，再同步输出 `PPT_HANDOFF.json`，使用 [交接协议](references/handoff-contract.md) 与 `scripts/check_handoff.py`。JSON 是索引，不覆盖任务书；发现不一致先对齐再派工。需要一次性枚举多项 JSON 结构错误或导出机器可读 Schema 诊断时，可在隔离 venv 按 [Schema 诊断说明](references/schema-diagnostics.md) 运行可选的 `scripts/check_handoff_schema.py`（结构通过不替代证据语义核验）。只编译任务且不涉及交接时，只交付 Markdown 并保留稳定 ID；即使没有 JSON，也统一用 M/C/E/R/V/S，R 同时编号外部检索与待用户补测、确认等获取任务，不另造编号；用户明确只要 Markdown 时，不额外生成 JSON 或 PPTX。
4. 涉及关键图表或设计参考时，按[逐页素材定位](references/handoff-contract.md#逐页素材定位)在任务书 04/07 节写明交给 APRD 的来源路线，06 节让 S/V 指向相应 R 或参考条目。交接前先做入口探查，把「精确直达」和「定向待找」分开；科学素材和版式参考各写自己的入口。06 节先定本版画法及升级条件；有 JSON 时，新交接用 `--strict-assets` 检查 READY 页的硬依赖。
5. 有新证据或设计/验收反馈时，不直接在下游抹掉科学条件。先回写主张、证据和页面影响；不足以支持结论时降级、改成问题或移出，保留异议、来源及变更记录。只重做受影响的资产或页面；重新检查这些页面及受影响的交付验收。

## 制作与交付

明确要求成品时，读取 [全栈路线](references/full-stack.md) 和 [交接协议](references/handoff-contract.md)。沿用已有模板、生成源和工具；没有则选择一条真实可运行的主制作路线，先做能力探针。检索、参考风格和制作都接收当前版本和具体任务 ID，返还实物路径、出处与缺口。深度研究和专业图形按需交给对应工具；只有在可用且获授权时才委派，单代理可执行同样的文件协议。

文件以实际存在、可重新打开、可核对为准。交付 PPTX 时运行构建与渲染、核对证据及可编辑性、记录发现和重验结果；区分结构检查、实际渲染、目视检查和目标软件实测。最终给用户可打开的交付链接以及尚待其确认的关键项。

显式调用示例：

```text
$academic-presentation-compiler 把这些材料编译成下周组会的任务书。先判断观众需要决定什么，只交付 PPT_REQUIREMENTS.md。
$academic-presentation-compiler 读取任务书和新增结果；修订受影响页面，然后生成可编辑 PPTX 并做学术和视觉验收。
```
